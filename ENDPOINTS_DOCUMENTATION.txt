================================================================================
F1 PROJECT API - COMPLETE ENDPOINTS DOCUMENTATION
================================================================================
Base URL: http://localhost:8000/api

This document contains all available API endpoints with examples and return types.
All endpoints return HTTP 200 with a readiness checklist, or HTTP 400/500 on error.


================================================================================
SECTION 1: SCHEDULE & RACE INFORMATION
================================================================================

1.1 Get Season Schedule
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/races/{year}/
PARAMETERS: None
PURPOSE:    Retrieve all races scheduled for a given year

EXAMPLE CALL (JavaScript):
  const response = await fetch('/api/races/2023/');
  const data = await response.json();

EXAMPLE CALL (cURL):
  curl "http://localhost:8000/api/races/2023/"

RETURN TYPE (JSON):
  {
    "year": 2023,
    "races": [
      {
        "round": 1,
        "date": "2023-03-05T23:45:00Z",
        "name": "Bahrain Grand Prix",
        "location": "Sakhir",
        "circuit": "Bahrain International Circuit",
        "country": "Bahrain"
      },
      ... more races
    ],
    "readiness": {
      "can_proceed": true,
      "available_data": ["schedule"],
      "unavailable_data": [],
      "message": null,
      "warnings": []
    }
  }

HTTP STATUS:
  200 - Success
  400 - Invalid year parameter

4.1 Get Lap Analysis
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/analysis/races/{year}/{round_number}/laps/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
QUERY:
  - session (str): Optional session type (R, Q, FP1, FP2, FP3). Default: R
  - driver (str): Optional 3-letter driver code (e.g., LEC, VER)
  - limit (int): Optional maximum rows to return (default: all)

PURPOSE:    Get lap-by-lap analysis with sector times and compound info

EXAMPLE CALL (JavaScript):
  const params = new URLSearchParams({
    driver: 'LEC',
    limit: 10
  });
  const response = await fetch(
    `/api/analysis/races/2023/1/laps/?${params}`,
    { method: 'GET' }

  const data = await response.json();

  curl "http://localhost:8000/api/analysis/races/2023/1/laps/?driver=LEC&limit=10"

5.1 Get Telemetry Snapshot (Single Driver, Single Lap)
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/analysis/races/{year}/{round_number}/telemetry/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
QUERY (REQUIRED):
  - driver (str): REQUIRED - 3-letter driver code (e.g., LEC, VER, HAM)
  - lap (int): REQUIRED - Lap number
QUERY (OPTIONAL):
  - session (str): Session type (R, Q, FP1, FP2, FP3). Default: R
  - limit_points (int): Maximum telemetry points to return
  - stride (int): Sample every N points (default: 1)
  - sector_start (int): Sector window start (1-3)
  - sector_end (int): Sector window end (1-3)

PURPOSE:    Get detailed telemetry data (position, speed, throttle, brake) for a single lap

SECTION 6: UNIFIED SERVICE ENDPOINTS
================================================================================
These endpoints retrieve multiple data types in a single call from a session.

6.1 Get Full Session Data (All Types)
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/unified/races/{year}/{round_number}/full-session/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
QUERY (REQUIRED):
  - include (str): REQUIRED - Comma-separated list of data types
    Valid types: telemetry, weather, pit_stops, incidents, positions, drs, track_status
QUERY (OPTIONAL):
  - session (str): Session type (R, Q, FP1, FP2, FP3). Default: R
  - driver (str): Optional driver filter

PURPOSE:    Retrieve multiple data types from a single session call
           Useful for getting comprehensive session data in one request

EXAMPLE CALL (JavaScript):
  const params = new URLSearchParams({
    include: 'weather,pit_stops,incidents',
    session: 'R'
  });
  const response = await fetch(
    `/api/unified/races/2023/1/full-session/?${params}`,
    { method: 'GET' }
  );
  const data = await response.json();

EXAMPLE CALL (cURL):
  curl "http://localhost:8000/api/unified/races/2023/1/full-session/?include=weather,pit_stops,incidents&session=R"

RETURN TYPE (JSON):
  {
    "meta": {
      "year": 2023,
      "round": 1,
      "session": "R",
      "requested_types": ["weather", "pit_stops", "incidents"],
      "cache_stats": {

SECTION 8: COMMON ERROR RESPONSES
================================================================================

8.1 400 Bad Request
────────────────────────────────────────────────────────────────────────────
Returned when:
  - Required query parameters are missing (e.g., driver, lap for telemetry)
  - Invalid parameter types (e.g., lap="abc" when integer expected)
  - Invalid session names (not in R, Q, FP1, FP2, FP3)

EXAMPLE RESPONSE:
  {
    "error": "driver query parameter is required",
    "error_code": "INVALID_PARAMETERS"
  }


8.2 404 Not Found
────────────────────────────────────────────────────────────────────────────
Returned when:
  - Race doesn't exist for given year/round
  - Driver not found in the race

EXAMPLE RESPONSE:
  {
    "error": "Race not found",
    "error_code": "RACES_DETAIL_NOT_FOUND",
    "readiness": {
      "can_proceed": false,
      "available_data": [],
      "unavailable_data": ["race_detail"],
      "message": "Race not found",
      "warnings": ["Race not found"]
    }
  }


8.3 200 with can_proceed=false (Data Unavailable)
────────────────────────────────────────────────────────────────────────────
Returned when:
  - Historical data not available (e.g., 1990 sessions)
  - Session data not supported by FastF1
  - Requested data type not available for the session

EXAMPLE RESPONSE:
  {
    "meta": {
      "year": 1990,
      "round": 1,
      "session": "FP1",
      "can_proceed": false,
      "available_data": [],
      "unavailable_data": ["telemetry", "laps"],
      "message": "Failed to load any schedule data. This session may not be supported by FastF1.",
      "warnings": ["Failed to load any schedule data..."]
    },
    "data": []
  }


8.4 500 Internal Server Error
────────────────────────────────────────────────────────────────────────────
Returned when:
  - Unexpected server error
  - Database connection issues
  - External service (FastF1) timeout

EXAMPLE RESPONSE:
  {
    "error": "Internal server error",
    "error_code": "ANALYSIS_TELEMETRY_ERROR",
    "detail": "Unexpected error occurred"
  }


================================================================================
SECTION 9: READINESS CHECKLIST STRUCTURE (In All Responses)
================================================================================

All endpoints return a "readiness" or "meta" object with the following structure:

  {
    "can_proceed": boolean,        // Whether the request can proceed with available data
    "available_data": [string],    // List of data types successfully available
    "unavailable_data": [string],  // List of data types unavailable
    "message": string or null,     // Brief message if can_proceed=false
    "warnings": [string]           // List of warnings (empty if can_proceed=true)
  }

INTERPRETATION:
  - If can_proceed=true: All requested data is available, use the response normally
  - If can_proceed=false: Data is partially or completely unavailable
    - available_data: Use these data types if present
    - unavailable_data: These were requested but not available
    - message: Human-readable explanation (displays to frontend users)
    - warnings: Detailed warnings about what's missing


================================================================================
SECTION 10: RATE LIMITING & PERFORMANCE NOTES
================================================================================

- No explicit rate limiting (but recommended for production)
- FastF1 API calls are cached at session level (SessionManager cache)
- Telemetry queries can return 100-2000 points per lap
  Use limit_points and stride parameters to reduce payload size
- For historical seasons (pre-2018), many endpoints may return can_proceed=false
- Weather and incident data not available for all sessions
