================================================================================
F1 PROJECT API - COMPLETE ENDPOINTS DOCUMENTATION
================================================================================
Base URL: http://localhost:8000/api

This document contains all available API endpoints with examples and return types.
All endpoints return HTTP 200 with a readiness checklist, or HTTP 400/500 on error.


================================================================================
SECTION 1: SCHEDULE & RACE INFORMATION
================================================================================

1.1 Get Season Schedule
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/races/{year}/
PARAMETERS: None
PURPOSE:    Retrieve all races scheduled for a given year

DESCRIPTION:
  Returns the full calendar for a given F1 season as an ordered list of races.
  The service checks the local database first (for seasons that have been
  persisted) and falls back to a live FastF1 API call if no stored data is
  found. Useful as the starting point for any season-level view — the round
  numbers returned here are what you pass into every other endpoint.

EXAMPLE CALL (JavaScript):
  const response = await fetch('/api/races/2023/');
  const data = await response.json();

EXAMPLE CALL (cURL):
  curl "http://localhost:8000/api/races/2023/"

2.1 Get Race Results (Qualifying + Race)
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/races/{year}/{round_number}/results/
PARAMETERS: 
  - year (int): F1 season year

QUERY:      None

PURPOSE:    Retrieve both qualifying and race results for a race

  readiness object reflects whether one or both sub-datasets are available so

2.3 Get Practice Session Results
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/races/{year}/{round_number}/practice/{session_name}/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
  - session_name (str): Session name (e.g., 'FP1', 'FP2', 'FP3')
QUERY:      None

PURPOSE:    Retrieve results from a specific practice session

DESCRIPTION:
  Returns the fastest-lap leaderboard for FP1, FP2, or FP3. The service
  prioritises lap-time data from the loaded session; if lap data is
  unavailable it falls back to the session results table (which carries
  best-lap information for older seasons). Passing an invalid session name
  (e.g. FP4) returns a 400 error immediately.

EXAMPLE CALL (JavaScript):
  const response = await fetch('/api/races/2023/1/practice/FP1/');
  const data = await response.json();

  curl "http://localhost:8000/api/races/2023/1/practice/FP1/"

RETURN TYPE (JSON):
  {
    "year": 2023,
    "round": 1,
    "session": "FP1",
    "results": [
      {
        "position": 1,
        "driver_name": "Max Verstappen",
        "constructor": "Red Bull Racing",
        "laps": 34,
        "best_lap": "1:31.456"
      },
      ... more practice results
    ],
    "readiness": {
      "can_proceed": true,
      "available_data": ["results"],
      "unavailable_data": [],
      "message": null,
      "warnings": []
    }

HTTP STATUS:
  200 - Success (can_proceed=false for historical unavailable sessions)

  500 - Server error

3.1 Get Driver Standings
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/drivers/{year}/
PARAMETERS: 
  - year (int): F1 season year
QUERY:      None

PURPOSE:    Retrieve driver championship standings for a season

DESCRIPTION:
  Queries the Ergast / Jolpica F1 standings API for the requested year and
  returns every driver's cumulative championship position, points tally, and
  win count at the end of that season. Two API URLs are tried in sequence so
  the service degrades gracefully if the primary source is down. When neither
  source responds successfully, the response still returns HTTP 200 with
  can_proceed=false and a human-readable message.

EXAMPLE CALL (JavaScript):
  const response = await fetch('/api/drivers/2023/');
  const data = await response.json();

EXAMPLE CALL (cURL):
  curl "http://localhost:8000/api/drivers/2023/"

RETURN TYPE (JSON):
  {
    "year": 2023,
    "standings": [
      {
        "position": 1,
        "driver_name": "Max Verstappen",
        "points": 575.0,
        "wins": 19,
        "constructor": "Red Bull Racing"
      },
      ... more standings
    ],
    "readiness": {
      "can_proceed": true,
      "available_data": ["standings"],
      "unavailable_data": [],
      "message": null,
      "warnings": []

HTTP STATUS:

4.1 Get Lap Analysis
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/analysis/races/{year}/{round_number}/laps/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
QUERY:
  - session (str): Optional session type (R, Q, FP1, FP2, FP3). Default: R
  - driver (str): Optional 3-letter driver code (e.g., LEC, VER)
  - limit (int): Optional maximum rows to return (default: all)

PURPOSE:    Get lap-by-lap analysis with sector times and compound info

DESCRIPTION:
  Returns one row per valid lap (laps with no recorded LapTime are excluded).
  Each row includes the driver, lap number, total lap time, all three sector
  times, the tyre compound, stint number, and whether the lap was a personal
  best. Use the `driver` filter to narrow to a single driver and `limit` to
  cap the result set. Supports all five session types (R, Q, FP1–FP3).

EXAMPLE CALL (JavaScript):
  const params = new URLSearchParams({
    driver: 'LEC',
    limit: 10
  });
  const response = await fetch(
    `/api/analysis/races/2023/1/laps/?${params}`,
    { method: 'GET' }
  );
  const data = await response.json();

EXAMPLE CALL (cURL):
  curl "http://localhost:8000/api/analysis/races/2023/1/laps/?driver=LEC&limit=10"

RETURN TYPE (JSON):
  {
    "meta": {
      "year": 2023,
      "round": 1,
      "session": "R",
      "row_count": 10,
      "limit_max": 2000,
      "can_proceed": true,
      "available_data": ["laps", "track_status"],
      "unavailable_data": [],
      "message": null,
      "warnings": []
    },
    "filters_applied": {
      "driver": "LEC",
      "limit": 10
    },
    "data": [
      {
        "driver_code": "LEC",
        "lap_number": 1,
        "lap_time": "0 days 00:01:37.123000",
        "sector1": "0 days 00:00:31.100000",
        "sector2": "0 days 00:00:33.000000",
        "sector3": "0 days 00:00:33.023000",
        "compound": "MEDIUM",
        "stint": 1,
        "is_personal_best": false
      },
      ... more laps
    ]
  }

HTTP STATUS:
  200 - Success
  400 - Invalid parameters
  500 - Server error


4.2 Get Pace Analysis
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/analysis/races/{year}/{round_number}/pace/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
QUERY:
  - session (str): Optional session type. Default: R
  - driver (str): Optional 3-letter driver code
  - limit (int): Optional maximum rows

PURPOSE:    Analyze pace evolution across laps for a driver

DESCRIPTION:
  Aggregates lap times per driver to expose median pace, best lap, and
  consistency (standard deviation). For Race sessions the service reads
  pre-computed DriverMetric rows from the database before falling back to a
  live FastF1 computation, making it fast for recently populated seasons.
  Ideal for building a driver pace-comparison chart across the grid.

EXAMPLE CALL (JavaScript):
  const response = await fetch(
    '/api/analysis/races/2023/1/pace/?driver=VER&session=FP1',
    { method: 'GET' }
  );
  const data = await response.json();

EXAMPLE CALL (cURL):
  curl "http://localhost:8000/api/analysis/races/2023/1/pace/?driver=VER&session=FP1"

RETURN TYPE (JSON):
  Similar to lap analysis, includes:
  {
    "meta": { ... },
    "filters_applied": { "driver": "VER", "limit": null },
    "data": [
      {
        "driver_code": "VER",
        "stint": 1,
        "lap_count": 15,
        "avg_pace": "0 days 00:01:32.456000",
        "min_pace": "0 days 00:01:30.123000",
        "max_pace": "0 days 00:01:35.789000",

4.3 Get Sector Analysis
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/analysis/races/{year}/{round_number}/sector-analysis/

QUERY:

5.1 Get Telemetry Snapshot (Single Driver, Single Lap)
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/analysis/races/{year}/{round_number}/telemetry/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
QUERY (REQUIRED):
  - driver (str): REQUIRED - 3-letter driver code (e.g., LEC, VER, HAM)
  - lap (int): REQUIRED - Lap number
QUERY (OPTIONAL):
  - session (str): Session type (R, Q, FP1, FP2, FP3). Default: R
  - limit_points (int): Maximum telemetry points to return
  - stride (int): Sample every N points (default: 1)
  - sector_start (int): Sector window start (1-3)
  - sector_end (int): Sector window end (1-3)

PURPOSE:    Get detailed telemetry data (position, speed, throttle, brake) for a single lap

DESCRIPTION:
  Streams car-data samples for one specific lap of one driver: speed (kph),
  throttle percentage, brake state, RPM, gear, and distance along the lap.
  Both `driver` and `lap` are required. Use `limit_points` and `stride` to
  downsample large payloads for charting, and `sector_start`/`sector_end`
  to zoom into a specific sector window (1–3) of the lap.

EXAMPLE CALL (JavaScript):
  const params = new URLSearchParams({
    driver: 'LEC',
    lap: 5,
    session: 'R',
    limit_points: 1000
  });
  const response = await fetch(
    `/api/analysis/races/2023/1/telemetry/?${params}`,
    { method: 'GET' }
  );
  const data = await response.json();

EXAMPLE CALL (cURL):

RETURN TYPE (JSON):

5.2 Get Telemetry Overlay (Compare Two Drivers, Same Lap)
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/analysis/races/{year}/{round_number}/telemetry/overlay/
PARAMETERS: 
  - year (int): F1 season year
  - round_number (int): Race round number
QUERY (REQUIRED):
  - driver_a (str): REQUIRED - First 3-letter driver code (e.g., VER)
  - driver_b (str): REQUIRED - Second 3-letter driver code (e.g., LEC)
QUERY (OPTIONAL):
  - session (str): Session type. Default: R
  - lap (int): Lap number (default varies by endpoint logic)
  - limit_points (int): Maximum points per driver
  - stride (int): Sample every N points (default: 1)

PURPOSE:    Compare telemetry traces of two drivers on the same lap (overlay comparison)

DESCRIPTION:

ENDPOINT:   GET /api/drivers/{driver_code}/career/
PARAMETERS:
  - driver_code (str): 3-letter FIA driver code (e.g., VER, HAM, LEC)

PURPOSE:    Retrieve a driver's complete career statistics across all seasons

DESCRIPTION:
  Returns full career summary including all seasons with wins, podiums, race
  count, and a `champion` flag indicating whether the driver won the WDC that

  4. Persists the result to DB so subsequent calls are served instantly.

7.2 Get Driver Season Breakdown
────────────────────────────────────────────────────────────────────────────
ENDPOINT:   GET /api/drivers/{driver_code}/{year}/
PARAMETERS:
  - driver_code (str): 3-letter FIA driver code (e.g., VER, HAM, LEC)
  - year (int): F1 season year (1950-2100)

PURPOSE:    Retrieve a driver's race-by-race results for a specific season

DESCRIPTION:
  Returns all races contested by a driver in a given season, including grid
  position, finish position, points earned, status (Finished/DNF/Retired), and
  whether they set the fastest lap. The service uses a multi-layer fallback:
  (1) fetches the season schedule from the local Race table or, if unavailable,
  from Jolpica's season schedule endpoint; (2) fetches per-round results from
  RaceResult DB rows or, if the DB is empty, from Jolpica's driver results
  endpoint (/ergast/f1/{year}/drivers/{driverId}/results/); (3) retrieves the
  driver's final season standing from Jolpica's driverStandings endpoint.
  All three fallbacks operate transparently — the endpoint returns full data
  even when DB tables are not yet populated. Returns can_proceed=false with
  empty races when the driver did not compete in that season or no data is
  available from any source. Year must be between 1950 and 2100; years outside
  this range are rejected with HTTP 200 and can_proceed=false.

  const response = await fetch('/api/drivers/HAM/2023/');

================================================================================
SECTION 10: READINESS CHECKLIST STRUCTURE (In All Responses)
================================================================================

All endpoints return a "readiness" or "meta" object with the following structure:

  {
    "can_proceed": boolean,        // Whether the request can proceed with available data
    "available_data": [string],    // List of data types successfully available
    "unavailable_data": [string],  // List of data types unavailable
    "message": string or null,     // Brief message if can_proceed=false
    "warnings": [string]           // List of warnings (empty if can_proceed=true)
  }

INTERPRETATION:
  - If can_proceed=true: All requested data is available, use the response normally
  - If can_proceed=false: Data is partially or completely unavailable
    - available_data: Use these data types if present
    - unavailable_data: These were requested but not available
    - message: Human-readable explanation (displays to frontend users)
    - warnings: Detailed warnings about what's missing

================================================================================
SECTION 11: RATE LIMITING & PERFORMANCE NOTES
================================================================================

- No explicit rate limiting (but recommended for production)
- FastF1 API calls are cached at session level (SessionManager cache)
- Telemetry queries can return 100-2000 points per lap
  Use limit_points and stride parameters to reduce payload size
- For historical seasons (pre-2018), many endpoints may return can_proceed=false
- Weather and incident data not available for all sessions
