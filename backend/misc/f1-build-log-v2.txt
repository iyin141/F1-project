02 Root Cause Analysis

THE SUPABASE PROBLEM

Why connecting to Supabase from Nigeria required the Session pooler and what each connection type means.

Direct Connection

db.ref.supabase.co : 5432

Resolves to IPv6 only on Nigerian networks. psycopg2 on Windows cannot connect over IPv6. DNS resolves fine but connection times out or fails. Not usable without IPv4.

Transaction Pooler

aws-0-eu-west-1.pooler.supabase.com : 6543

Stateless pooler for serverless/short-lived connections. Requires postgres.ref username format. Not ideal for Django which uses persistent connections. Was causing Tenant or user not found errors.

Session Pooler Solution

aws-1-eu-west-1.pooler.supabase.com : 5432

Supabase's recommended option for IPv4 networks. Uses port 5432 (same as direct). Resolves to IPv4. Requires postgres.ref username. This is what finally worked.

Key Lesson

aws-0 vs aws-1 matters

Transaction pooler is aws-0-region. Session pooler is aws-1-region. Same region (eu-west-1), different load balancer. One character difference, completely different behavior.

Performance Analysis

FastF1 cold loads are expensive

Qualifying/race/practice endpoints can be slow when sessions load raw data repeatedly. Cache enablement plus selective session.load flags are now part of the default backend strategy.

Bracket Analysis

Heavy payload analysis endpoints (implemented)

Default endpoints remain lean for UI speed, while opt-in analysis routes now provide heavy payload workflows (laps, stints, pace, telemetry snapshot, overlay, summary, tyre strategy, and sector analysis).

04 Lessons Learned

WHAT WE KNOW NOW

Every mistake made and concept learned useful reference for the rest of the build.

Topic Lesson Type 

config() 
Takes a variable name ('SECRET_KEY'), not the value itself. config('django-insecure-...') is wrong it looks for a key with that name in .env. 
Error 

cast=bool 
config('DEBUG', cast=bool) converts string "True" to Python True. cast=True is wrong True is a value, not a type. 
Error 

venv activation 
Always activate venv before running manage.py. Check for (venv) prefix in terminal. Without it, Django isn't importable. 
Django 

startproject . 
The dot in django-admin startproject f1_project . creates the project in the current directory. Without it, Django makes a nested subfolder. 
Django 

Thin views 
Views call services and return responses. All FastF1 and pandas logic lives in api/services/. Never put business logic directly in views.py. 
Concept 

IPv6 vs IPv4 
Nigerian ISPs resolve Supabase direct connection hosts to IPv6 only. psycopg2 on Windows can't use IPv6. Session pooler resolves to IPv4 use that. 
Network 

Pooler username 
Transaction and session poolers require postgres.projectref as the username, not just postgres. Direct connection uses just postgres. 
Network 

aws-0 vs aws-1 
Transaction pooler host starts with aws-0. Session pooler host starts with aws-1. Same region, completely different endpoint and behavior. 
Network 

changepassword 
python manage.py changepassword username resets a superuser password. python manage.py shell -c "..." lists all users if username is forgotten. 
Django 

venv prompt trap 
(venv) in terminal prompt is not enough. Verify active interpreter with python -c "import sys; print(sys.executable)". Wrong interpreter can show ModuleNotFoundError even when Django exists in another venv. 
Error 

FastF1 cache 
Enable cache once via fastf1.Cache.enable_cache(...). The cache directory must exist first (mkdir(..., exist_ok=True)) or FastF1 raises NotADirectoryError. 
Django 

session.load flags 
Use minimal data loading for non-telemetry endpoints: disable telemetry/weather/messages when not needed to reduce request time and bandwidth. 
Concept

Detailed Test-Run Caveat (Network/DNS)

During focused unit test execution in this environment, Django test DB initialization failed before tests could run because PostgreSQL host resolution failed:
- psycopg2 OperationalError: could not translate host name "aws-1-eu-west-1.pooler.supabase.com" to address: Name or service not known

Why this blocks tests:
- Django test runner creates or connects to a test database before executing tests.
- The default DB host is Supabase pooler DNS.
- When DNS resolution fails locally, Django cannot establish the connection needed for test DB setup.
- As a result, tests abort in setup phase, even if application code and imports are valid.

Conclusion:
- This is infrastructure/network name-resolution failure in the local environment, not a Python syntax/import failure in the readiness implementation.

Additional portability caveat discovered and resolved:
- Running unit tests on SQLite initially failed on api migration SQL containing PostgreSQL-specific CASCADE syntax.
- Resolution: f1_project.settings_test now sets MIGRATION_MODULES = {"api": None} so unit/focused suites use model sync for api app under SQLite.
- Result: focused regression suite (55 tests) passes under --settings=f1_project.settings_test without Supabase DNS dependency.

TRACK B - API Client and Error Handling Layer

Goal

Build a reusable HTTP client with consistent behavior for success, timeout, network failures, and backend error responses.

Client

lib/api/client.ts

Centralize base URL, JSON headers, timeout, and interceptors for logging and normalization.

Services

lib/api/services.ts

Expose focused functions like getSeasonSchedule(year) with typed return data and clear thrown errors.

Error Strategy (reference) Notes 

Network failure (backend down): show "Cannot reach backend"
4xx (invalid request/year): show friendly message from API
5xx (server error): show "Server error, try again later"
Timeout (>10s): show "Request timed out" with retry action

Recommended flow:
Component calls getSeasonSchedule(2024)
-> service calls GET /races/2024/
-> interceptor handles low-level errors
-> component receives typed data OR displays user-facing error
